## Description

Implement environment/auth visibility and token lifecycle management UI using the website golden template as the baseline. Covers two screens: environment-auth (showing active auth mode, endpoint, and current actor identity) and token-management (list tokens, view token details, create/revoke tokens).

**Starting point**: `.volon/templates/website-golden-template/environment-auth.html`, `token-management.html`

**API contracts to surface**:
- `GET /v1/auth/status` (or equivalent) — active auth mode, endpoint, current actor
- `GET /v1/auth/tokens` — list managed tokens with id, name, scopes, expiry, revoked status
- `POST /v1/auth/tokens` — create a new token (show generated value once, then hide)
- `DELETE /v1/auth/tokens/{id}` — revoke a token

**Context for the agent**: Auth in this system has two modes: no-auth (local use) and managed-token (multi-agent/multi-client use). The environment-auth screen should make the current mode obvious so operators don't accidentally think they're in a secured environment when they're not. Token management is a privileged operation — creating and revoking tokens should be explicit, auditable, and never silent. Generated token values must be shown exactly once after creation with a clear "copy this now" prompt. Tokens should show their scope and namespace_globs once the capability token model is in place (see TASK-20260228-015).

## Acceptance

- [ ] Environment-auth screen shows: active auth mode (no-auth vs token), endpoint URL, current actor identity, and connection health.
- [ ] Token list shows: token name/id, creation date, expiry, scopes, revoked state.
- [ ] Token creation flow: form with name/expiry/scopes fields → submit → show generated value once → confirm copy → return to list.
- [ ] Token revocation requires explicit confirmation before executing.
- [ ] Screen does not imply capabilities unsupported by the current backend (e.g., hide scope fields if capability tokens not yet implemented).
- [ ] All token mutations are visible in the audit log (verify via audit screen after each operation).

## Verification

- [ ] Create a token, copy the value, close the modal — verify the value is no longer visible.
- [ ] Revoke a token — verify it appears as revoked in the list and any request using it fails.
- [ ] Confirm that the environment screen correctly reflects the auth mode configured in the running server.
