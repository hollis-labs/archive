## Description

Create the new public repository as a clean directory, copy the export scope
(from TASK-20260301-002) into it, and initialize it as a git repo. This is
the foundation all subsequent tasks work against.

## Steps

1. Create new directory at `~/Projects-apps/<new-name>/` (or wherever the
   user wants public repos)
2. Copy files per the scope defined in TASK-20260301-002
3. `git init` + initial commit ("initial export from volon-dev workspace")
4. Verify the repo builds and tests pass in the new location:
   ```bash
   cd ~/<new-name>
   go build ./...
   go test -race ./...
   ```
5. Create GitHub repo at `github.com/<org>/<new-name>` (empty, no README)
6. Push initial commit

## Acceptance
- [ ] New directory exists with only export-scope files
- [ ] No `.volon/`, `volon.yaml`, `SPEC-TASKS/`, `artifacts/`, Volon docs present
- [ ] `go build ./...` succeeds in new location
- [ ] `go test -race ./...` passes
- [ ] GitHub repo created and initial commit pushed
- [ ] `README.md` placeholder in place (full README is TASK-20260301-006)

## Notes

- The dev workspace (`context-memory-service/`) remains intact and continues
  to be used for ongoing development. The public repo is the export target.
- Do not use `git clone` or `git subtree` — just copy the files to keep
  history clean and intentional for the v0.1.0 release.
- If the binary is renamed in TASK-20260301-004, confirm the directory
  name and CMD path are correct in the export.
