## Description

This task implements tag-based filtering for the `Select` and packet endpoints. It is the Option B implementation for TASK-20260228-005 — only proceed with this task if TASK-20260228-005 chose Option A (defer tags) and this is now being scheduled explicitly, OR if TASK-20260228-005 chose Option B (implement now). Check that task's status before starting.

**What to implement**:

1. **Schema**: Add `metadata_json TEXT` column to the `records` table (if not already present — check first). Add a new `record_tags(record_id TEXT, tag TEXT)` table indexed on `(tag)` and `(record_id, tag)`.

2. **Write path**: When `AppendRecord` receives a record with metadata that includes a `tags` field (array of strings), parse it and insert one row per tag into `record_tags`. If no tags, skip gracefully.

3. **Select**: When `tags_any: ["foo", "bar"]` is present in the selector, add a JOIN against `record_tags` to filter records. A record matches if it has at least one of the requested tags.

4. **Re-add `tags_any` to View spec**: After this is implemented and tested, update `docs/SPECS/VIEWS.md` to re-add `tags_any` as a supported field. Remove the "planned feature" note added by TASK-20260228-005.

**Minimal model** — keep it simple:
- Tags are strings only. No tag namespacing, no hierarchies.
- A record with no tags simply has no rows in `record_tags`.
- Deleting a record must cascade-delete its `record_tags` rows.
