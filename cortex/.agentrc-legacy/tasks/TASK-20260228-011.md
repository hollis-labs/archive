## Description

The context packet endpoint (TASK-20260228-010) needs a deterministic token/byte estimation function to enforce `max_tokens_estimate` budget limits. This must never require a model call — it's a pure heuristic function.

**Pre-condition**: TASK-20260228-010 should be in progress or complete. This task can be worked in parallel but must be integrated into the packet handler.

**Estimation model (stable heuristic)**:

The function takes a record payload (bytes) and returns an estimated token count:

```go
func EstimateTokens(payload []byte) int {
    // Simple heuristic: ~4 bytes per token (common approximation for English/code)
    // Round up to nearest integer
    return (len(payload) + 3) / 4
}
```

This is intentionally simple and deterministic. It does not attempt to count actual BPE tokens — that would require a model-specific tokenizer and would break determinism.

**Where it's used**:
- In the packet assembly loop: after each record is added, accumulate `total_tokens_estimate += EstimateTokens(record.Payload)`. Stop when `total_tokens_estimate >= max_tokens_estimate`.
- In the manifest: report `tokens_estimate` as the sum of all included records' estimates.

**Additional**: Add a `POST /v1/context/estimate` utility endpoint that accepts a list of record IDs and returns their byte + token estimates without fetching full payloads. This is useful for agents planning their context budget before a full packet retrieval.

```
POST /v1/context/estimate
{ "keys": ["user/memory/pref-1", "user/cache/task-ctx"] }

Response:
{ "keys": [...], "total_bytes": 12800, "total_tokens_estimate": 3200 }
```
