## Agent Context

**Why this is the most important task in the MVP**: The context packet is the primary "agent continuity" product surface. An agent resuming work, booting into a project, or handing off context uses `context packet` to get a budget-bounded, manifest-annotated snapshot of everything relevant. Without this, agents must assemble context themselves using multiple `context get` calls.

**What already exists** (read these before implementing):
- `internal/contextstore/store.go` — `Select()` function with selector support (namespaces, keys, revision_scope, order, limit). The packet endpoint builds on top of Select.
- `internal/contextapi/server.go` — `handleView` (line ~116) wraps Select. The packet handler follows a similar pattern but adds assembly logic on top.
- `internal/contextcli/cli.go` — `runView()` (line ~394) shows how the CLI calls the view endpoint. `runPacket()` follows the same pattern for the packet endpoint.
- `docs/SPECS/VIEWS.md` — the selector model. Packets use the same selector; they just add budget + manifest on top.

**Key constraint**: Token estimation must NEVER call a model. Use `bytes / 4` as a rough estimate.

**Pins behavior**: `user/pins/*` records are always prepended to the results when `include_pins: true` (the default). Fetch them via a secondary `Select` on `user/pins/*` before the main selector results.

## What to Build

### 1. API endpoint (internal/contextapi/)

```
POST /v1/context/packet
Content-Type: application/json
```

Request body:
```json
{
  "selector": {
    "namespaces": ["user/memory/*", "user/cache/*"],
    "keys": [],
    "revision_scope": "head",
    "order": "created_desc",
    "limit": 100
  },
  "assembly": {
    "include_pins": true,
    "time_window": {
      "since": "2026-01-01T00:00:00Z",
      "until": "2026-02-27T00:00:00Z"
    },
    "budget": {
      "max_items": 50,
      "max_bytes": 102400,
      "max_tokens_estimate": 8000
    },
    "shape": {
      "include_payload": true,
      "payload_mode": "full",
      "fields_whitelist": []
    },
    "manifest_level": "summary"
  }
}
```

Response:
```json
{
  "items": [...],
  "manifest": {
    "request_id": "req-abc123",
    "selector_normalized": {...},
    "pins_included": 3,
    "items_total": 47,
    "items_returned": 20,
    "bytes_returned": 40960,
    "tokens_estimate": 5120,
    "truncated": true,
    "truncation_reason": "budget.max_items",
    "sources": { "user/memory": 10, "user/cache": 8, "user/pins": 3 }
  }
}
```

**Assembly logic** (implement in order):
1. If `include_pins: true`, fetch `user/pins/*` (head revision) — these always come first.
2. Run the main selector to fetch candidate records.
3. Apply `time_window` filter if provided (filter by `created_at`).
4. Walk candidates in selector order; add each to `items` until a budget limit is hit.
5. Budget checks: stop when `len(items) >= max_items` OR `bytes_so_far >= max_bytes` OR `tokens_estimate_so_far >= max_tokens_estimate`.
6. If `payload_mode: head_only`, truncate each payload to first 512 bytes.
7. Build and return the manifest.

**Implementation note**: Token estimation = `sum(len(record.payload)) / 4`. No model call, ever.

Add the route to `server.go`: `case r.Method == http.MethodPost && r.URL.Path == "/v1/context/packet"`.

### 2. CLI command (internal/contextcli/)

```bash
# Basic usage — get context for current work
context packet --namespace "user/memory/*" --namespace "user/cache/*"

# With budget limit
context packet --namespace "user/memory/*" --budget-items 20 --budget-tokens 4000

# Include pins (default: true)
context packet --namespace "user/*" --no-pins

# JSON output for agent consumption
context packet --namespace "user/memory/*" --output json

# Save manifest alongside items
context packet --namespace "user/*" --manifest full --output json

# Time-windowed
context packet --namespace "user/cache/*" --since 2026-02-01T00:00:00Z
```

**Output modes**:
- Default (human): print a summary table: `N items, M bytes (~K tokens) from X namespaces. Truncated: yes/no`
- `--output json`: print the full response JSON (items + manifest). This is what agents pipe to their context window.
- `--output manifest-only`: print only the manifest JSON (useful for logging/debugging)

Add `runPacket()` in `cli.go`. Parse flags: `--namespace` (repeatable), `--budget-items`, `--budget-bytes`, `--budget-tokens`, `--since`, `--until`, `--no-pins`, `--payload-mode (full|head-only)`, `--manifest (summary|full)`, `--output (human|json|manifest-only)`.
