## The Agent Workflow to Verify

Start with a clean environment (`contextd` running with `--managed-auth`).

### Step 1 — Bootstrap namespaces

```bash
# Register tiered namespaces
context namespace register user/memory --actor user
context namespace register user/cache --actor user
context namespace register user/pins --actor user
context namespace register app/test/draft --actor app:test
context namespace register app/test/session/task-001 --actor app:test
```

Expected: All namespaces register without error. Verify with `context namespace show user/memory`.

### Step 2 — Create a scoped token for the app agent

```bash
context token create \
  --name test-agent \
  --client-id app:test \
  --scopes write,packet,promote.request \
  --namespaces "app/test/*"
```

Expected: Token value displayed once. Token ID returned. `context token list` shows it.

### Step 3 — App writes session context

```bash
# Using the app token
context put app/test/session/task-001 state \
  --actor app:test \
  --token <app-token> \
  --data '{"task": "MVP verification", "phase": "integration"}'
```

Expected: Record written. `context get app/test/session/task-001 state` returns the record.

### Step 4 — App writes to user/memory (should FAIL)

```bash
context put user/memory/task-001 state \
  --actor app:test \
  --token <app-token> \
  --data '{"attempt": "direct write to user namespace"}'
```

Expected: **403 policy_denied**. Apps cannot write directly to `user/*`.

### Step 5 — User writes pins

```bash
context put user/pins/project-context project \
  --actor user \
  --data '{"project": "context-memory-service", "mvp_phase": "integration"}'
```

Expected: Written successfully.

### Step 6 — Get a context packet

```bash
context packet \
  --namespace "app/test/session/*" \
  --namespace "user/memory/*" \
  --output json | jq '.manifest'
```

Expected:
- `pins_included >= 1` (the project-context pin)
- `items_returned > 0`
- `manifest.request_id` is non-empty
- Audit log has a matching entry

### Step 7 — Use the broker

```bash
context broker plan \
  --intent resume_task \
  --summary "MVP verification integration test"
```

Expected: Returns a plan with namespace patterns derived from the summary + `user/pins/*` included.

```bash
context broker fetch \
  --intent resume_task \
  --summary "MVP verification integration test"
```

Expected: Returns items + manifest. No error.

### Step 8 — Promotion workflow

```bash
# App proposes a draft for promotion
context put app/test/draft/pref-v1 user-preference \
  --actor app:test \
  --token <app-token> \
  --data '{"preference": "verbose output", "confidence": 0.9}'

# App requests promotion to user memory
context promote request \
  --source-namespace app/test/draft \
  --source-key user-preference \
  --target-namespace user/memory/preferences \
  --target-key test-preference \
  --reason "High-confidence preference detected in session"
```

Expected: Promotion request created with status=pending.

```bash
# User approves
context promote list  # see pending requests
context promote approve <request-id> --notes "Looks correct"

# User applies
context promote apply <request-id>
```

Expected: Record appears in `user/memory/preferences/test-preference`. Audit log shows 3 linked entries.

### Step 9 — Maintenance

```bash
# Trim expired cache records
context maintenance trim --namespace "app/test/session/*" --dry-run
context maintenance trim --namespace "app/test/session/*"
```

Expected: Dry-run shows what would be trimmed. Actual trim executes without error. Audit log has trim entry.

### Step 10 — Token revocation

```bash
context token revoke <app-token-id>

# Try to use the revoked token
context put app/test/session/task-001 state \
  --token <revoked-token> \
  --data "test"
```

Expected: Write attempt returns `401 auth_required` with reason=revoked.
