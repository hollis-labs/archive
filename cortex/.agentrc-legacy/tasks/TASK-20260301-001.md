## Description

Choose the public name for the Context Memory Service and define the minimum
viable visual identity before any public-facing work begins. Everything else
in the release sprint is blocked on this decision.

## Scope

1. **Name** — pick the final public name
   - Check `docs/ideation-naming-001.md` for prior naming work (written for
     Volon/orchestration, but the aesthetic direction is relevant)
   - The service is a persistent, namespaced, revision-tracked memory store
     for AI agents. Name should signal: durable, structured, agentic memory.
   - Single word preferred; compound acceptable if tight.
   - Avoid: "memory", "cache", "store" as standalone (too generic).
     Avoid: SaaS/dashboard vibes, trendy AI buzzwords.

2. **Domain** — confirm the chosen name has an available .com (or .dev/.io
   as fallback). Check before committing to the name.

3. **GitHub slug** — confirm `hollis-labs/<name>` is available, or decide
   on org/repo structure.

4. **Binary name** — `contextd` is a placeholder. Decide whether to keep it
   or rename it (e.g. `<name>d` or just `<name>`).

5. **Visual identity direction** — minimal brief only (not full design):
   - Color palette (1–2 primaries)
   - Logo style (wordmark? icon? icon + wordmark?)
   - Aesthetic register (minimal/technical vs. warm/approachable)
   - This brief feeds the website task (TASK-20260301-014).

## Acceptance
- [ ] Name confirmed and documented
- [ ] Domain availability confirmed

- [ ] Binary name decision made
- [ ] Visual identity brief written (can be a short paragraph or bullet list)
