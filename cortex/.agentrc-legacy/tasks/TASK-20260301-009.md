## Description

The HTTP API (`internal/contextapi/`) is fully implemented but has no
user-facing reference document. `docs/SPECS/API.md` is an internal spec,
not a user reference. Write `docs/API-REFERENCE.md` for the public repo.

## Coverage

For each endpoint, document:
- Method + path
- Auth requirement (Bearer token? which scope?)
- Request body (JSON schema, required vs optional fields)
- Response shape (success + error)
- Brief example (curl)

Endpoints to cover (from `internal/contextapi/server.go`):
- `POST /v1/records` — write a record
- `GET /v1/records/{namespace}/{key}` — head
- `GET /v1/records/{namespace}/{key}/history` — history
- `GET /v1/view` — view selector
- `POST /v1/context/packet` — context packet
- `POST /v1/promote/request` — request promotion
- `GET /v1/promote` — list promotions
- `POST /v1/promote/{id}/approve` — approve
- `POST /v1/promote/{id}/apply` — apply
- `POST /v1/namespaces` — register namespace
- `GET /v1/namespaces/{namespace}` — show namespace
- `GET /v1/audit` — audit log
- `POST /v1/tokens` — create token
- `GET /v1/tokens` — list tokens
- `DELETE /v1/tokens/{id}` — revoke token

## Acceptance
- [ ] `docs/API-REFERENCE.md` exists in public repo

- [ ] Auth requirements are accurate (verify against `internal/contextapi/server.go`)
- [ ] At least one curl example per endpoint
- [ ] Error shapes documented (at minimum: auth_required, insufficient_scope, not_found)
