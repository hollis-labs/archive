## Description

Write practical documentation for two audiences:

**Humans** — someone who just cloned the repo and wants to understand what this is
and get it running in under 10 minutes.

**Agents** — a local Claude Code agent that needs to understand how to configure
the MCP server and what tools are available.

## What's missing today

The existing `docs/` are all internal implementation specs and Volon system docs.
There is no:
- README for the context memory service itself (the root README is about Volon)
- Quick-start guide
- MCP setup guide (the MCP spec covers rollback evidence retention; it does not say
  "put this in your .mcp.json")
- CLAUDE.md snippet an agent can load for context about the service

## Deliverables

1. **Root README update** (or new `README-CONTEXT-SERVICE.md`)
   - What the service is and why you'd use it (1 paragraph)
   - Install and run (3 commands)
   - First write + first read (copy-paste example)
   - MCP setup (the .mcp.json block from TASK-022)
   - Link to full docs

2. **`docs/QUICKSTART.md`** — human quick-start
   - Build: `go build ./cmd/contextd`
   - Run: `contextd serve`
   - Create a token: `contextd token create --name my-agent --scopes write,packet`
   - Write a record: `contextd put user/memory/task-001 state --data '{"phase":"start"}'`
   - Read it back: `contextd get user/memory/task-001 state`
   - Get a packet: `contextd packet --namespace "user/memory/*"`
   - Configure MCP in Claude Code

3. **`docs/AGENT-SETUP.md`** — agent-specific guide
   - What tools are available and when to use them
   - Recommended namespace conventions for agent memory
   - Token setup (what scopes to request)
   - Example session lifecycle (boot via context_packet, write observations, request promotions)
   - `.mcp.json` example with working args

4. **Update `docs/SPECS/MCP.md`** status from "planned" to "implemented"
   - Trim the 20+ rollback/evidence/archival subsections (those belong in an operator
     runbook, not the primary spec)
   - Add practical "Getting started" section at the top

## Notes
