## Description

Implement operational observability screens for audit/event/incident workflows using the website golden template as the baseline. Covers: audit event list, event detail, incident list, and incident detail. This is the "what happened and why" surface — agents and operators use it to trace auth failures, policy rejections, promotion events, and consistency scan results.

**Starting point**: `.volon/templates/website-golden-template/audit-ops.html`, `event-detail.html`, `incident-detail.html`

**API contracts to surface**:
- `GET /v1/audit/events` — paginated event list with filters (type, actor, namespace, time window)
- `GET /v1/audit/events/{id}` — single event with full payload
- `GET /v1/audit/incidents` (or equivalent) — incident list
- `GET /v1/audit/incidents/{id}` — incident detail with evidence links

**Context for the agent**: The audit log is the ground truth for debugging determinism failures. Events must be shown in deterministic order (by timestamp + sequence). Filtering by namespace, actor, and event type are the three most common debugging patterns. Incidents should show the chain: trigger event → affected records → resolution status. Auth failures, policy violations, and checksum mismatches are the most important incident types to surface prominently.

## Acceptance

- [ ] Audit event list renders with deterministic ordering controls (timestamp, type, actor, namespace filters all functional).
- [ ] Event detail shows full payload: actor, namespace, key, operation, timestamp, request_id, policy decision.
- [ ] Incident list and detail screens are implemented with evidence linkage visible (which events triggered the incident).
- [ ] Auth/policy/validation failure events are visually distinguished from informational events (color, icon, or badge).
- [ ] Empty state, loading state, and error state are handled for all list and detail views.
- [ ] Filtering is deterministic — applying a filter always produces the same ordered result set.

## Verification

- [ ] Manually trigger an auth failure and confirm it appears in the audit log with correct metadata.
- [ ] Confirm that navigating from an incident to the triggering event works (deep-link or inline reference).
- [ ] Confirm pagination/cursor behavior doesn't lose ordering context between pages.
