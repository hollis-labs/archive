## What to Build

Three maintenance actions, exposed via both an API endpoint and a CLI command.

### 1. Store-level implementations (internal/contextstore/)

**Trim** — delete records whose `created_at` is older than `now - retention` for namespaces with a `retention` duration in their policy. Applies to `cache` and `session` tiers.
- Must be idempotent (safe to run repeatedly).
- Must write one audit log entry per trim run (not per record): action=trim, namespace_pattern, records_affected, actor, timestamp.
- Returns: count of records trimmed.

**Compact** — for namespaces with `max_revisions` in policy, keep only the most recent N revisions per (namespace, key). Delete older revisions from both DB and file store.
- Only runs on explicit request; never automatic.
- Returns: count of revisions deleted.

**Tombstone** — when a record is deleted/redacted in a namespace where the policy has `redaction.tombstone_on_delete: true`, write a tombstone payload (`{"redacted": true, "at": "<iso8601>", "actor": "<actor>"}`) instead of hard-deleting the row. Where tombstone is false, hard-delete.
- This modifies the delete path in AppendRecord or adds a separate DeleteRecord function.

### 2. API endpoints (internal/contextapi/)

```
POST /v1/maintenance/trim
  Body: { "namespace_pattern": "user/cache/*" }
  Auth: actor=user required
  Response: { "trimmed": 12, "namespace_pattern": "user/cache/*", "duration_ms": 45 }

POST /v1/maintenance/compact
  Body: { "namespace_pattern": "app/myapp/draft/*" }
  Auth: actor=user required
  Response: { "compacted": 8, "namespace_pattern": "app/myapp/draft/*", "duration_ms": 23 }
```

Add both routes to the switch in `server.go`. Both require `authorizeMutatingRequest`.

### 3. CLI command (internal/contextcli/)

```
context maintenance trim [--namespace <pattern>] [--dry-run]
context maintenance compact [--namespace <pattern>] [--dry-run]
```

- `--namespace` defaults to `user/cache/*` if not specified (most common use case)
- `--dry-run` prints what would be trimmed/compacted without actually doing it
- Output (success): `Trimmed 12 records from user/cache/*`
- Output (dry-run): `Would trim 12 records from user/cache/* (dry-run, no changes made)`
- Output (nothing to do): `Nothing to trim in user/cache/* (0 records matched retention policy)`
- Errors print to stderr with the error code from the API response

Add a `runMaintenance` dispatch function in `cli.go` following the same pattern as `runNamespace`.
