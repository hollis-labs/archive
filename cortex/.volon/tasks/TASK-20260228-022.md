## Agent Context

**Pre-condition**: TASK-20260228-021 must be complete (read tools working).

**Auth for mutating tools**: The adapter was started with `--mcp-token <token>`. That
token is loaded from the Store via `ValidateAuthTokenWithClaims` at each mutating call.
Read tools pass through without token check. Write/promote tools validate the token's
scopes before executing.

If no token was provided at startup (`--mcp-token` empty), mutating tools return:
```json
{"code":"auth_required","message":"no capability token configured for mutating operations"}
```

If the token lacks the required scope:
```json
{"code":"insufficient_scope","message":"token does not have scope: write"}
```

**What to implement** (replace the 3 mutating stubs from TASK-020):

### context_packet

The primary agent continuity surface. Maps to the existing `handlePacket` / `store.Select`
+ pin assembly logic.

Tool input schema:
```json
{
  "namespaces": {
    "type": "array",
    "items": { "type": "string" },
    "description": "Namespace glob patterns to include, e.g. [\"user/memory/*\", \"app/test/session/*\"]"
  },
  "include_pins": { "type": "boolean", "default": true },
  "max_items": { "type": "integer", "default": 50 },
  "max_tokens_estimate": { "type": "integer", "default": 8000 },
  "payload_mode": { "type": "string", "enum": ["full", "head_only"], "default": "full" }
}
```

Response:
```json
{
  "items": [ ... ],
  "manifest": {
    "request_id": "...",
    "items_returned": 12,
    "pins_included": 2,
    "budget_used_estimate": 4200,
    "truncated": false
  }
}
```

Auth: read-only result, no token required (consistent with HTTP endpoint in mvp-open-read
posture). If a token IS provided, apply namespace glob filtering from the token's
`namespace_globs` (same as HTTP handler).

### context_write

Maps to `store.Write(ctx, record)`.

Requires `write` scope in the configured token.

Tool input schema:
```json
{
  "namespace": { "type": "string" },
  "key": { "type": "string" },
  "payload": { "type": "object", "description": "Arbitrary JSON payload" },
  "actor": { "type": "string", "description": "Actor identity, e.g. app:my-agent" },
  "record_type": { "type": "string", "default": "state", "description": "Record type tag" }
}
```

Response:
```json
{ "record_id": "rec_...", "revision": 1 }
```

Error cases:
- No token / missing scope → `auth_required` / `insufficient_scope`
- Namespace policy violation → `policy_denied`
- Validation error (missing fields) → `validation_error`

### context_promote_request

Maps to `store.CreatePromoteRequest(ctx, ...)`.

Requires `promote.request` scope.

Tool input schema:
```json
{
  "source_namespace": { "type": "string" },
  "source_key": { "type": "string" },
  "target_namespace": { "type": "string" },
  "target_key": { "type": "string" },
  "reason": { "type": "string" }
}
```

Response:
```json
{ "request_id": "req-...", "status": "pending" }
```

## Example .mcp.json configuration (document in response)

After this task, an agent can configure:
```json
{
  "mcpServers": {
    "context": {
      "command": "contextd",
      "args": [
        "--mcp",
        "--db", "/Users/<you>/.context/context.db",
        "--mcp-token", "tok_abc123"
      ]
    }
  }
}
```

The token needs scopes `write,packet,promote.request` and namespace_globs appropriate
for what the agent is writing to.
