## Description

Records written via `context_typed_write` with `record_type` (e.g. `decision/adr`, `strategy/roadmap`, `system/map`) are stored and visible via `context_view`, but `context_typed_view` returns 0 items.

## Reproduction

1. Write a record with type:
   ```
   contextd put --namespace app/mentat --key test-adr --type decision/adr --status canonical --payload '{"title":"test"}'
   ```
2. Verify it exists via generic view:
   ```
   contextd view --namespace app/mentat  # shows the record
   ```
3. Query typed view:
   ```
   contextd typed-view --view strategy  # returns 0 items
   ```

## Expected behavior

The `strategy` view is configured with types `[strategy/goal, strategy/constraints, strategy/roadmap, decision/adr, system/map]`. A record with `record_type=decision/adr` should appear in `strategy` view results.

## Current state

- 12 content types registered (all correct)
- 2 views defined: `strategy` (30 max), `task_exec` (50 max)
- 5 typed records written to `app/mentat` namespace (2 ADRs, 1 roadmap, 1 system map, 1 vision)
- Both views return `{"count":0,"items":[]}`

## Likely cause

The view query likely filters on a `type_id` column or field that isn't being populated when records are written via `context_typed_write`, or the join/filter logic doesn't match the storage format.

## Acceptance criteria

- [ ] `typed_view` returns records matching registered types
- [ ] Rank weights apply (canonical=1.0, draft=0.5, etc.)
- [ ] Existing 5 typed records in `app/mentat` appear in strategy view after fix
