## Description

Right now the system is a versioned KV registry with namespaces, but it has no first-class distinction between "working context cache" (short-lived, task-scoped) and "durable memory" (curated, versioned facts). This task formalizes the tier model by defining canonical namespace conventions and writing the default policy JSON for each tier.

**Canonical tiers and their namespace patterns**:

| Tier | Namespace pattern | Semantics |
|---|---|---|
| `memory` | `user/memory/*` | Curated durable facts; slow-changing; conflict-aware |
| `cache` | `user/cache/*` | Working context; expirable; aggressively trimmed |
| `pins` | `user/pins/*` | Always-include; user-asserted constraints and preferences |
| `draft` | `app/<id>/draft/*` | App-owned draft content pending promotion |
| `session` | `app/<id>/session/<task-id>/*` | Ephemeral task-scoped working context |

**What this task produces**:
1. A `docs/SPECS/NAMESPACES.md` spec doc defining the five tiers, their namespace patterns, ownership rules, and intended lifecycle.
2. Default policy JSON snippets for each tier (to be used in TASK-20260228-008 when the policy schema is extended).
3. An update to `docs/SPECS/STORAGE.md` that references the tier model.

**This task is doc/spec only** — no code changes. The policy schema extension is TASK-20260228-008. The maintenance jobs are TASK-20260228-009. This sequencing allows TASK-20260228-008 to use this spec as its reference.

**Key ownership rules to codify**:
- `user/*` namespaces: `actor=user` required for all write/promote operations.
- `app/<id>/*` namespaces: apps may only write within their own `<id>` pattern.
- No app may write directly to `user/*` (promotion workflow is the only bridge).
