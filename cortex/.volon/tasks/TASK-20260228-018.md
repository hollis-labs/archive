## Description

The broker planning endpoint (TASK-20260228-017) produces retrieval plans. This task adds the server-side validation layer that enforces caps before the plan is executed. Even if the broker produces a valid-looking plan, the validation gate ensures no plan can exceed configured server defaults or reach forbidden namespaces.

**Pre-condition**: TASK-20260228-017 must be complete.

**Validation rules to enforce**:

1. **Namespace scope check**: Each namespace pattern in `plan.selector.namespaces` must match at least one of the calling token's `namespace_globs`. Patterns that don't match are stripped and added to `warnings`. If no namespaces remain after stripping, return `403` with:
   ```json
   { "error": "plan_forbidden", "detail": "no permitted namespaces in plan" }
   ```

2. **Budget cap enforcement**: Server has configurable default caps (e.g., `max_items: 200`, `max_tokens_estimate: 32000`). If the plan's budget exceeds these caps, clamp to the server's cap and add a warning. Never return an error for over-budget plans — clamp silently with a warning.

3. **Forbidden namespace patterns**: A server-side blocklist of namespace patterns that can never be included in a broker plan (e.g., `system/*`, `internal/*`). If any requested namespace matches a forbidden pattern, strip it with a warning.

4. **Plan size check**: If a plan's `selector.limit` exceeds `max_items`, clamp it. If the plan requests `payload_mode: full` on a restricted namespace, downgrade to `head_only`.

**Configuration** (in `contextd` server config or CLI flags):
```yaml
broker:
  max_items_cap: 200
  max_tokens_cap: 32000
  forbidden_namespace_patterns: ["system/*", "internal/*"]
```

**Where validation runs**: In the `/v1/broker/plan` handler, after the broker produces the plan, before returning the response. The validated (possibly clamped) plan is what's returned to the caller.

## Acceptance

- [ ] A plan requesting a forbidden namespace has that namespace stripped + warning added.
- [ ] A plan with budget over the server cap has budget clamped + warning added.
- [ ] A plan with no permitted namespaces returns `403 plan_forbidden`.
- [ ] All validation is applied before the plan leaves the `/v1/broker/plan` response.
- [ ] Server caps are configurable (not hardcoded).
