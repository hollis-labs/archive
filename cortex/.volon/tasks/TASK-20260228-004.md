## Description

Run a final hardening pass across all GUI screens implemented in sprint-2026-03-gui-template. This task is a quality gate — it should only begin after TASK-20260228-001 through TASK-20260228-003 and TASK-20260225-239 through TASK-20260225-242 are marked done. The goal is a stable, documented GUI baseline that future sprints can iterate on without regressions.

**Scope**:
1. **Responsiveness**: validate that all screens render correctly at desktop (1280px+), tablet (768px), and mobile (375px) breakpoints.
2. **Accessibility (a11y)**: run an axe or Lighthouse a11y audit; fix any critical/serious issues (color contrast, missing labels, keyboard navigation order).
3. **Known gaps**: document any screens or features that are placeholder-only or not yet wired to live data — capture as backlog items, not loose comments.
4. **Docs handoff**: write or update implementation notes in `user-docs-mini-site/` covering: how to run the GUI locally, which API endpoints each screen uses, and the expected data states (empty, loading, error, populated).

**Context for the agent**: The GUI is built on the website-golden-template. The hardening pass is not a full redesign — it's a tightening pass to catch layout breaks, inaccessible elements, and undocumented placeholders before future agents start iterating on top of the baseline. New backlog items are the correct output for gaps found, not inline fixes to unrelated screens.

## Acceptance

- [ ] All implemented screens pass basic responsiveness check at 375px, 768px, 1280px without horizontal overflow or broken layouts.
- [ ] No critical or serious a11y violations per axe/Lighthouse audit (warnings are documented but not blocking).
- [ ] All known placeholder screens are listed in a `GUI-GAPS.md` file with a one-line description and a backlog item reference.
- [ ] `user-docs-mini-site/` has a "Running the GUI" page covering: local dev setup, API endpoint map per screen, and data state documentation.
- [ ] Implementation notes are written for engineers/designers — not marketing copy.

## Verification

- [ ] Run `axe` or `npx lighthouse` against each screen and confirm no critical issues remain unfixed.
- [ ] Open each screen at 375px width in browser devtools — no horizontal scroll, no overflow.
- [ ] Confirm `GUI-GAPS.md` exists and references at least one backlog item per gap.
