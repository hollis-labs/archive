## What to Build

### 1. Three API endpoints (internal/contextapi/)

**`POST /v1/context/promote/request`** — App creates a promotion request

Auth requirement: token with `promote.request` scope + token's `namespace_globs` must cover the source namespace.

```json
Request:
{
  "source_namespace": "app/myapp/draft/pref-v2",
  "source_key": "pref-v2",
  "source_revision_id": "abc123",
  "target_namespace": "user/memory/preferences",
  "target_key": "user-prefs",
  "reason": "Observed consistent user preference pattern",
  "proposed_summary": "Brief description of what this record contains"
}

Response 200:
{ "request_id": "req-xyz789", "status": "pending" }

Response 400 (validation failure):
{ "error": "validation_error", "detail": "source record not found or revision mismatch" }

Response 403 (policy):
{ "error": "policy_denied", "detail": "apps cannot target user/* directly; use promote.request" }
```

Implementation:
1. Validate source record exists and revision matches.
2. Validate target namespace is a `user/*` or otherwise permitted by policy.
3. Write a `promote.request` record to `app/<client_id>/promotions/<request-id>` using `AppendRecord`.
4. Emit audit event: `promote.request.created` with request_id, source, target, actor.

---

**`POST /v1/context/promote/approve`** — User approves a pending request

Auth requirement: `actor=user` (token with `promote.approve` scope).

```json
Request:
{ "request_id": "req-xyz789", "notes": "Looks correct, approve" }

Response 200:
{ "approval_id": "appr-123", "request_id": "req-xyz789", "status": "approved" }

Response 404:
{ "error": "not_found", "detail": "promotion request req-xyz789 not found" }

Response 409:
{ "error": "already_approved", "detail": "request has already been approved" }
```

Implementation:
1. Read the `promote.request` record (look it up by request_id across `app/*/promotions/`).
2. Validate it exists and is in `pending` status.
3. Write a `promote.approve` record to `user/promotions/<approval-id>`.
4. Update the `promote.request` status field to `approved`.
5. Emit audit event: `promote.request.approved`.

---

**`POST /v1/context/promote/apply`** — Apply an approved promotion

Auth requirement: `actor=user` (token with `promote.apply` scope).

```json
Request:
{ "request_id": "req-xyz789" }

Response 200:
{ "record_id": "rec-newid", "request_id": "req-xyz789", "approval_id": "appr-123" }

Response 400:
{ "error": "not_approved", "detail": "this request has not been approved" }
```

Implementation:
1. Read `promote.request` record; verify status=approved.
2. Read the corresponding `promote.approve` record; verify it references this request_id.
3. Fetch the source record payload (by source_revision_id).
4. Call `AppendRecord` to write the payload to the target namespace/key with `actor=user`.
5. Update `promote.request` status to `applied`.
6. Emit audit event: `promote.request.applied` with request_id, approval_id, new record_id.

**Deprecate the old endpoint**:
- `POST /v1/context/promote` should return `410 Gone` with body:
  `{"error": "deprecated", "detail": "Use /v1/context/promote/request, /v1/context/promote/approve, /v1/context/promote/apply"}`

### 2. CLI commands (internal/contextcli/)

```bash
# App creates a promotion request
context promote request \
  --source-namespace app/myapp/draft \
  --source-key pref-v2 \
  --target-namespace user/memory/preferences \
  --target-key user-prefs \
  --reason "User confirmed preference in session"

# User lists pending promotion requests
context promote list [--status pending|approved|applied|all]

# User approves a request
context promote approve req-xyz789 [--notes "LGTM"]

# User applies an approved request
context promote apply req-xyz789

# One-shot: approve and apply in sequence (shorthand for user workflow)
context promote accept req-xyz789 [--notes "LGTM"]
```

Output for `promote request`:
```
Promotion request created.
  Request ID:  req-xyz789
  Status:      pending
  Source:      app/myapp/draft/pref-v2 (rev abc123)
  Target:      user/memory/preferences/user-prefs
  Reason:      User confirmed preference in session
  Next step:   context promote approve req-xyz789
```

Output for `promote list`:
```
ID           STATUS    SOURCE                          TARGET                           REQUESTED
req-xyz789   pending   app/myapp/draft/pref-v2         user/memory/preferences/prefs    2026-02-27 10:00
req-abc123   applied   app/claude/draft/learned-v1     user/memory/project-a/context    2026-02-26 14:23
```

Output for `promote approve`:
```
Approved promotion request req-xyz789.
  Approval ID: appr-456
  Next step:   context promote apply req-xyz789
```

Output for `promote apply`:
```
Promotion applied.
  Record ID:   rec-newid
  Target:      user/memory/preferences/user-prefs
  Audit trail: req-xyz789 → appr-456 → rec-newid
```

Add `runPromote` dispatch function in `cli.go`. Subcommands: request, list, approve, apply, accept.
