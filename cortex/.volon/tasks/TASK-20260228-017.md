## Agent Context

**Pre-conditions**: TASK-20260228-010 (context packets) and TASK-20260228-016 (capability token enforcement) must be complete. The broker plan output must be a valid `POST /v1/context/packet` request body.

**What this is**: The broker is a convenience layer — not a model, not an authority. An agent often knows what it's doing ("resume task X", "boot for project Y") but doesn't know exactly which namespaces or keys to query. The broker translates intent into a precise, policy-safe packet request. The broker **never executes the retrieval** — it only produces a plan. The agent then calls `/v1/context/packet` with that plan.

**Critical constraint**: The broker must NEVER call an LLM. For MVP it uses deterministic heuristics based on `intent` type. It can be evolved later to use a model — but the output contract (a valid packet request) stays the same.

**What already exists** (read these before implementing):
- `internal/contextapi/server.go` — route dispatch, capability token patterns.
- `internal/contextapi/` — `handlePacket` (from TASK-20260228-010). The broker output is a `PacketRequest` struct.

## What to Build

### 1. API endpoint (internal/contextapi/)

```
POST /v1/broker/plan
Content-Type: application/json
```

Request body:
```json
{
  "task_summary": "Resume implementation of capability token enforcement. Previous work in user/memory/task-015.",
  "intent": "resume_task",
  "constraints": {
    "namespaces": ["user/memory/*", "user/cache/*"],
    "max_items": 50,
    "max_tokens_estimate": 4000
  }
}
```

Response:
```json
{
  "plan": {
    "selector": {
      "namespaces": ["user/memory/task-015*", "user/memory/sprint-2026-08*"],
      "revision_scope": "head",
      "order": "created_desc",
      "limit": 50
    },
    "assembly": {
      "include_pins": true,
      "budget": { "max_items": 50, "max_tokens_estimate": 4000 },
      "shape": { "include_payload": true, "payload_mode": "full" },
      "manifest_level": "summary"
    }
  },
  "rationale": "resume_task: targeting namespace patterns derived from task_summary keywords + always including user/pins/*.",
  "warnings": []
}
```

**Heuristics for each intent type** (deterministic, no model):

- `resume_task`: Extract keywords from `task_summary` (lowercase split on spaces, filter stopwords). Build namespace patterns: `user/memory/<keyword>*` for the top 3 keyword matches. Always include `user/pins/*`. Budget = constraints.max_items or default 50.

- `boot_project`: Include `user/memory/*` + `user/pins/*` with full budget (default max_items=100). Time window: no filter (get everything relevant).

- `review_session`: Include `user/cache/*` with time_window = last 24h. Include `user/pins/*`. Budget = constraints.max_items or default 30.

- `custom`: Use constraints.namespaces directly if provided; otherwise use `user/*`. Budget from constraints.

**What the broker cannot do** (enforce these):
- Cannot include namespaces outside the calling token's `namespace_globs`. Strip forbidden namespaces and add a warning.
- Cannot request budget above server-configured caps. Clamp and add a warning.
- Cannot target `system/*` or any namespace in the server's forbidden_patterns list.

### 2. CLI command (internal/contextcli/)

```bash
# Get a retrieval plan for the current task
context broker plan \
  --intent resume_task \
  --summary "Implementing capability token enforcement in phase 4"

# Boot context for a project
context broker plan --intent boot_project

# Review recent session
context broker plan --intent review_session

# Execute the plan immediately (plan then packet in one step)
context broker fetch \
  --intent resume_task \
  --summary "Resume phase 4 token work"

# Output plan as JSON (for piping to context packet manually)
context broker plan --intent resume_task --summary "..." --output json
```

Output for `context broker plan` (human):
```
Broker plan for intent: resume_task

  Namespaces:   user/memory/task-015*, user/memory/sprint-2026-08*
  Include pins: yes
  Budget:       50 items, 4000 tokens estimate
  Rationale:    resume_task: targeting patterns derived from "capability token enforcement phase 4"

  To execute this plan:
    context packet --namespace "user/memory/task-015*" --namespace "user/memory/sprint-2026-08*" --include-pins --budget-items 50 --budget-tokens 4000

  Or: context broker fetch --intent resume_task --summary "..."
```

Output for `context broker fetch` (human):
```
Fetching context via broker plan...
  Plan: resume_task → 2 namespace patterns + pins
  Result: 12 items, 8.4KB (~2100 tokens). Not truncated.
  Manifest saved to: .context-packet-manifest.json
```

Add `runBroker` dispatch in `cli.go`. Subcommands: `plan`, `fetch`. `fetch` calls `/v1/broker/plan` then immediately pipes the result to `/v1/context/packet` and returns items + manifest.
